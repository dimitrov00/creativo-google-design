# P0 exit-criteria proofs

`pnpm run verify:p0` builds the functions, writes their flag env and runs `verify-p0.mjs` inside fresh firestore, auth, functions and storage emulators. It proves the client-details P0 exit criteria that need the whole stack (design §12.4 P0): the seed runs twice at ONE instant with the same result (appointments, users, client records and stats), a double backfill is byte-equal apart from `updatedAtUtcMs`, the seed's stats equal the backfill's for every client record a seat names (`subjectCustomerIds` → `clientStats/{customerId}`, money in `restricted/money` as `lifetimeSpendCents`), a staff edit of the seeded party of two audits each person (one `BOOKING_STAFF_MOVE` row per person's client record, `targetCustomerId`, actor `ADMIN`), and a profile name change is audited by field name only (`PROFILE_UPDATED`, `profileFields`, targeting the account; flip-2 plan F2-5, Phase 4a 4A-3 (3) / 4A-16): the client's DIRECT write of their own name is denied by the rules and leaves no row, and the `updateProfile` callable — the rename, then the name put back — writes exactly one row per call in its own transaction, credited to the client (`USER`, §10.15), the profile trigger skipping the event its `profileEditedAtUtcMs` marker names; the restore re-derives the search keys from the stored contact so the profile ends with the seed's name and search keys. Since flip 1 every document it reads is the flat archetype body (Law 5) — since flip 2 the `users` bodies too, its own sysadmin account included (built by the seed's `registeredAccountBody`, `tools/seed/fixtures/users.fixtures.ts`): the backfill's progress is `backfillJobs/clientStats.finishedAtUtcMs` with its `sampleChecked`/`sampleMismatched`, and the party is re-read on `utcEpochMs`, `localDate` and `startMinutes`. Since Phase 4a (4A-4) every callable payload is its flipped call component too: the move is `commands: [{ editCommand: 'MOVE', localDate, startMinutes, seatIds: null }]` (the shop's wall clock), the backfill `{ backfillJobName: 'CLIENT_STATS', backfillResume, cursor }`, `updateProfile` `{ firstName, lastName, birthDate }` with `null` for keep; the minted claims carry the tenant (`tenantId`, as `verifyOtp` mints them). The script also runs against a live `pnpm run dev` stack (`node tools/verify/p0/verify-p0.mjs`); it rebuilds `clientStats` from scratch and puts back the party and the name it edits (the name through `updateProfile`). Between steps it waits for the function triggers to go quiet with `tools/seed/settle.mjs`, the same wait the e2e suite runs (as `node tools/seed/settle.mjs`) after its one seed. Each wait counts from the instant its step began, so a trigger the seed or the backfill set off that died before the wait connected is still reported by name.

The settle watches the trigger executions on the Logging emulator, and it refuses to run without one: a wait on the data alone once called a trigger storm quiet. `verify:p0` starts one with `START_LOGGING_EMULATOR=true`, and a live `pnpm run dev` stack has one through `--ui`. The workspace's pinned firebase-tools (a root devDependency, 15.31.0, which every package script runs) also starts it when the variable is unset, but only by accident (the settle's header explains why), so start any other hub with one of the two. Against a hub without a Logging emulator this script fails at its first settle: it offers no data-only opt-out, because its proofs are only as good as the wait. The settle keeps that opt-out for other callers who knowingly accept the weaker wait: `allowDataOnly: true` in process, `--allow-data-only` on its CLI.

The two seed runs share ONE instant (audit-hardening Phase 3, P3-DEP-2): before the first run the script captures it — your `SEED_NOW` when set, in any form the seed reads (epoch milliseconds, a wall time on the shop's clock such as `SEED_NOW=2026-10-27T23:40`, an ISO instant with `Z` or an offset), else the clock once — and hands it to both runs as `SEED_NOW` (`seed-run.mjs`, proved by `node --test tools/verify/p0/seed-run.spec.mjs`; the text is read by the seed's own `seedNowOf`, from its bundle). Each run reading its own clock used to make (a) differ whenever one of today's visits ended, or the shop's midnight passed, between the runs. A malformed `SEED_NOW` stops (a) before the first run. The settle waits keep the real clock: they compare with the Logging emulator's real entry times. The seed's stats projection keeps the real clock too, so (c) still compares two real-clock answers.

The backfill runs loop the `runBackfill` callable the way any runner should. Each call answers within its own work budget (49 s, sized from the callable SDK's 70 s default wait), and the script waits up to 600 s for it, longer than the callable's 540 s platform timeout, so it never abandons a call the server is still working on. If an answer is lost anyway — no answer in time, a dropped connection, or a body that arrives cut off, empty or unreadable (only a well-formed `{error}` is a refusal; see `callable-answer.mjs`, proved by `node --test tools/verify/p0/callable-answer.spec.mjs`) — the script does not re-send the request: it calls again with `backfillResume: true`, and the server continues from `backfillJobs/clientStats`. The run's totals and its sample are read from that document at the end.

The first proof needs no emulator: `(f)` reads the dependency keys of the functions build's generated `dist/apps/functions/package.json`. It first refuses a forbidden key — `@angular/*`, `luxon`, `@types/luxon`, `dinero.js` (`FORBIDDEN_FUNCTIONS_DEPS`): the blueprint's end-of-Phase-3b assertion, kept as code once Phase 4a took `@angular/*` and `luxon` out of the dist and Phase 4b `dinero.js` (`rxjs` stays: Nx scans ecs-core, whose ports name `Observable`, Phase 4a plan 4A-15, §10.1) — and then compares the keys with `functions-deps.baseline.json` (the ECS migration's Phase 1 gate — a new graph edge, even one from a project's `eslint.config.mjs`, silently grows the deploy's runtime dependencies). It lives in `functions-deps.mjs` (proved by `node --test tools/verify/p0/functions-deps.spec.mjs`) and runs alone after a build: `pnpm nx build functions && node tools/verify/p0/check-functions-deps.mjs`. Re-record the baseline with `--record` only for an intended change, and say why in the commit; the record refuses a forbidden key too, so none can enter the baseline.
