## Recommendations on the §12 owner questions

1. **Cap on repeating blocks.** Neither option as asked. Keep the 366-occurrence limit and add a span limit: the end date at most one year after the series starts.
   - The code's comments already promise this ("a year of them", `recurrence-rule.data.ts:114`; "no call materialises more than a year of days", `recurrence.system.ts:328`), but nothing enforces it.
   - Refusing at the 2-month horizon is too tight. Staff block weeks they cannot sell yet, and the horizon can grow. With no write-ahead job, those days would be lost.
2. **Week view (F-25).** Change the comments to "all chairs" (`staff-day.store.ts:183-184`, `:1102`).
   - The code follows the 2026-09-23 ruling (chair only in links, for the shared front-desk iPad, `:977-982`).
   - A one-chair default would name no chair for that iPad.
3. **Law 3 sentence.** Adopt it, with the bounded series named, replacing the existing lazy-evaluation bullet. Suggested text:

   > Truth is stored as a pattern, plus one document per day that departs from it. An open-ended repeat is never written ahead day by day; a dated series is bounded (at most a year) and written once. A derived value is worked out when read unless a privacy boundary, a busy screen's read fan-out or a transaction's conflict set requires it; then it is stored as a projection that can be rebuilt and that expires.
