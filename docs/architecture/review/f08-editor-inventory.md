## E. Behaviour bugs noticed (by reading; none run, none fixed)

- **BUG-1, «За кого» on a stored seat saves nothing.** `setLegClient` (6718) changes `leg.clientId`. `savedShape` omits it, so the sheet stays clean and no «Запази» appears. If something else is saved, `commandsFor` reads `clientId` only for ADDED seats (`staff-edit-plan.system.ts:479`), and `booking-call.data.ts` has no command for it. The chip shows the new person, and it is lost on close without the discard guard. Spec :6588 and :6699 only exercise minted (`draft-`) seats.
- **BUG-2, a variant on a stored seat never travels.** `pickLegVariant` (2508) changes `variantId` and the price. No edit command carries a variant, and `typedPriceCents` stays null, so no REPRICE. With equal minutes the sheet is not dirty; with different minutes only REDURATE goes. The adoption effect (1974-1981) keeps the drafted variant, so the sheet shows one variant over a stored other. Comment 2110 half-admits the shape; the control still offers it. **The two largest findings: both may want a command, or a removed control, not a move.**
- **BUG-3, the dock's preview disagrees with applying.** VE-2. With an exclusive coupon on the bill and a typed figure, the dock previews both; «Приложи» drops the coupon (`withAdded`).
- **BUG-4, `seen.has('chair')` (3035) is always false.** The key never exists since 2026-09-09, so the roster-less fallback lists the chair twice when a leg sits on it. Fallback path only.
- **BUG-5 (suspected), `dirty` is order-sensitive, the plan order-blind.** `savedShape` stringifies discounts in order; `commandsFor` compares as a set (`sameBill`). Removing and re-adding two stacking coupons raises «Запази», the batch has no DISCOUNTS, and the draft never adopts the seed's order. The same could follow any save if the server re-sorts.
- **BUG-6, two floors.** A typed duration floors at 5 (`typedSpan`, `html:1840`); the frame refuses under 10 (`html:1700`). A 5-minute visit can be typed that the frame's drag cannot make. The comment at `html:1830` says they are one.
- **BUG-7, `lastVisitDate` formats in the raw language (7643).** `en` reads en-US, against OR-5/DEP-F4's en-GB. Announcement only.
- **BUG-8, latent: `t('staff.visit.currencySymbol')` (html 862, 2565) beside a bill in `vm.currency`.** DEP-21 made the bill's currency real (spec :1754 prints лв.); these two units did not follow.
