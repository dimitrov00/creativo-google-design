# Accessibility conventions

House style for the design system (`libs/ui/*`) and every feature built on it: `data-*` is a pure styling hook with zero assistive-technology (AT) meaning; `aria-*` (and the native semantics of the element) carries all AT-relevant state. Style off `data-*`. Never mirror state into `aria-*` just to style it, and never select on a hand-authored `aria-*` attribute — pair it with a `data-*` hook driven by the same signal. The one exception is an ARIA attribute a component _owns_ as the single source of truth (see [styling-conventions.md](./styling-conventions.md), the grammar).

| Attribute pattern                                               | Purpose                                                                       | When to use                                                                                                                                    | Reference                                                                                                                                              |
| --------------------------------------------------------------- | ----------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `data-button-style` / `data-control-size` / `data-tone` / …     | Visual variant selection, zero AT meaning                                     | Any component with mutually-exclusive style variants                                                                                           | `.ui-button[data-button-style='bordered']`                                                                                                             |
| `data-spread` / `data-on-media` / `data-icon-only`              | Layout/visual toggles, zero AT meaning                                        | Boolean style toggles (empty-string-or-null)                                                                                                   | `ui-button` (`libs/ui/controls/src/lib/button/button.ts`)                                                                                              |
| `data-invalid` **paired with** `aria-invalid`                   | Style hook mirrored 1:1 from a real ARIA attribute, single source signal      | Whenever a styling data-attribute has AT-relevant meaning — always pair, driven from one input/signal                                          | `ui-text-field` (`libs/ui/controls/src/lib/text-field/text-field.ts`) — canonical template, reuse verbatim; `ui-code-field`                            |
| `aria-expanded` / `aria-disabled` styled directly               | An ARIA attribute the component itself owns as the single source of truth     | Only when no parallel `data-*` exists for the same state — a second attribute would duplicate it                                               | the expand chevron (`libs/ui/icons/src/lib/icon/icon.css`), the disabled gate (`libs/ui/modifiers/modifiers.css`)                                      |
| `role="status"` / `aria-live`                                   | Only for content that _dynamically updates_ and should be announced           | Opt-in only — never on static content; `role="alert"` only for a refusal that must interrupt                                                   | `ui-toast` (`role="status"`, polite); `ui-notice`'s `uiAnnounce` (`note` by default, `status` when polite, `alert` when assertive); `ui-count-stepper` |

| `aria-describedby`                                              | Associates a control with the text that explains it                           | Whenever a message, unit or hint element exists alongside a form control or a dialog's question                                                | `ui-unit-field` / `ui-amount-field` (the unit), `ui-alert` (the message)                                                                               |

## Non-interactive by default

`ui-card` (`libs/ui/patterns/src/lib/card/card.ts`) as an element has no `role` or `tabindex` — it is not interactive, and any interactive affordance inside it (a `Book now` button) is its own real focusable element. A pressable card is a real `<a uiCard>` or `<button uiCard>` with `uiInteractive`, never a `<div>` with `role="button"` + `tabindex="0"` bolted on — that anti-pattern re-implements native keyboard activation, focus, and AT semantics by hand and reliably gets at least one of them wrong. The same holds for rows (`a[uiListRow]`, `button[uiListRow]`) and quick actions (`a[uiQuickAction]`, `button[uiQuickAction]`). Where a whole surface is already the control, button chrome inside it is the decorative `span[uiButton]`, hidden from AT with `aria-hidden` on the cluster — never a nested real button.

## Disabled, busy and motion

- A host that is itself activatable (`<button>`, `<a>`) uses the native `disabled` attribute; a surface that only claims it uses `aria-disabled="true"`. Every hover and press rule is gated against `:disabled`, `[aria-disabled='true']` and `[data-disabled]`, so a disabled surface never lights up; the disabled cursor is one recipe in `modifiers.css`.
- A button at work is not a button asleep: `uiLoading` keeps the label's box, draws the ring, takes no pointer, and says why with `aria-busy`.
- The OS "reduce motion" preference wins globally (`libs/ui/tokens/reduced-motion.css`); motion that carries meaning opts out with `data-motion-essential` and states its own reduced-motion treatment. Press scales drop to `none` under reduced motion.

## Dialogs, sheets and announcements

- A yes/no question is `ui-alert`, built on the native `<dialog>` shown modally — the top layer, the focus trap and Escape come from the platform. Return gives the preferred answer.
- Sheets (`ui-sheet`, `ui-modal-sheet`) share `UiSheetBehavior` (`libs/ui/layout/src/lib/sheet/sheet-behavior.ts`): the body scroll lock, the focus trap and its restore, Escape, and `inert` on the page chrome behind them. A stacked sheet takes the top layer over the one beneath.
- Visually hidden text for AT only is `uiVisuallyHidden`, never an ad-hoc off-screen class.

## Contrast

Words meet 4.5:1 with a margin: the house floor is 4.6:1 (`libs/ui/tokens/src/lib/accent-rule.spec.ts`, `contrast.ts`). That is why the accent law keeps small words in ink — the raw accent as small type is 3.04:1 on white — and why quiet words on a fill take `--sys-color-secondary-label-on-fill`.

## Canonical templates to copy from

- **`data-invalid`/`aria-invalid` pairing:** `ui-text-field` (`libs/ui/controls/src/lib/text-field/text-field.ts`).
- **`aria-pressed` toggle:** `button[uiChip]` (`libs/ui/controls/src/lib/chip/chip.ts`).
- **Switch:** `button[uiSwitch]` (`libs/ui/controls/src/lib/switch/switch.ts`).
- **Opt-in live region:** `ui-toast` (`libs/ui/patterns/src/lib/toast/toast.ts`) and `ui-notice`'s `uiAnnounce` (`libs/ui/patterns/src/lib/notice/notice.ts`).
- **`aria-busy` + activation guard:** `ui-button`'s `uiLoading` (`libs/ui/controls/src/lib/button/button.ts`).
- **Modal question:** `ui-alert` (`libs/ui/patterns/src/lib/alert/alert.ts`).
