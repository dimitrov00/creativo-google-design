**Three findings change the specification, not only the plan:**

- **S-1 (cd-1-2)** — CUJ 2's link opens the **agenda**, where free time is drawn as pressable
  rows: `/staff/schedule?day=<Tuesday>&view=agenda&barber=ivan&free=1`. `free=1` is read once in
  the dashboard's route inputs (`staff-dashboard.ts:806-815`) and calls a new non-persisting
  `ScheduleStatusFilter.showFreeTimeOnce()`; the parameter is dropped from the URL after it is
  applied, so `queryParamsHandling: 'merge'` does not carry it on.
- **S-2 (ir-1-4)** — erasure never meets a link: it refuses staff accounts and a linked account
  holds the barber role. The spec's "erasing the account clears them too" becomes this invariant;
  the erasure items are dropped.
- **S-3 (ir-1-3)** — a `setRoles` decision table for every (role change, link change) pair,
  recorded in the spec.
